# Lo que ejecuta código en NUESTRA máquina al compilar.
#
# Cada línea es `<objeto-git> <ruta>`. Lo genera y lo compara
# `conocimiento/lo-que-corre-al-compilar`.
#
# UNA LÍNEA NUEVA AQUÍ ES CÓDIGO NUEVO QUE CORRE AL COMPILAR. Antes de
# aceptarla, mírala: es el vector por el que entraron los gusanos de npm
# y del AUR — no un paquete nuevo, una VERSIÓN nueva de uno que ya usabas.
#
# QUÉ ENTRA: el script de construcción de cada crate —el declarado con
# `build =`, no solo el que se llama `build.rs`—, todo `.rs` que ese
# script arrastre por `mod` o `include!`, las fuentes NATIVAS que compila
# o enlaza (`.c`, `.S`, `.o`, `.a`…), los crates proc-macro y las
# librerías que un `[build-dependencies]` nombra.
#
# NO SE FILTRA POR PLATAFORMA, y es deliberado: entran también los `.a` de
# `winapi-*-windows-gnu`, que en Linux no se enlazan nunca. Filtrar por el
# objetivo de HOY dejaría la superficie ensancharse en silencio el día que
# se cruce-compile. El manifiesto no se lee entero: se lee su DIFF.
#
# LO QUE ESTO **NO** DICE, y se escribe porque decía lo contrario hasta el
# 2026-08-14: NO es «el único momento en que puede entrar algo». El árbol
# del PRODUCTO está congelado; el VERDE no. El CI hace `cargo install` de
# cargo-audit y cargo-deny, que NO pasan por `vendor/` —medido: `cargo
# install` ignora la sustitución de fuentes— y compilan sus propios
# `build.rs` sin vigilar. Lo dijo la revisión de seguridad de ese día.
#
# TAMPOCO cubre lo que ENTRA en el binario sin correr al compilar: el
# `src/` de cada crate. Eso lo cubre el anclaje contra crates.io
# (`cargo vendor` a un temporal + `diff -r`), que hoy es un comando en un
# comentario y no un paso — está registrado como tarea.
#
# Esto NO es una barrera criptográfica: quien pueda escribir en vendor/
# puede escribir aquí. Lo que hace es que el cambio se VEA en el diff.
